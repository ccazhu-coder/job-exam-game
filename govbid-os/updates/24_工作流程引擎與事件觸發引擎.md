# GovOps OS｜第24檔：工作流程引擎與事件觸發引擎

## 目標

建立 GovOps OS 的自動化核心。

讓系統不只是記錄資料。

而是：

- 自動建立流程
- 自動建立後續工作
- 自動更新關聯資料
- 自動通知
- 自動檢查缺件
- 自動修復流程

正式建立 GovOps OS Workflow Engine 與 Event Engine。

--------------------------------------------------
【一、工作流程引擎】
--------------------------------------------------

## 核心概念

Workflow Engine 負責：

- 流程順序
- 流程依賴
- 自動建立後續工作
- 狀態流轉
- 流程中斷處理

## 工作流程資料表

工作流程紀錄

欄位：

- 流程ID
- 組織ID
- 活動ID
- 流程類型
- 流程名稱
- 流程狀態
- 啟動時間
- 完成時間
- 負責人
- 錯誤訊息
- 建立時間
- 更新時間

## 流程狀態

- 待執行
- 執行中
- 已完成
- 部分完成
- 發生錯誤
- 已取消

--------------------------------------------------
【二、活動建立工作流程】
--------------------------------------------------

## 建立活動後

Workflow Engine 自動執行：

1. 建立活動資料
2. 建立Google Drive資料夾
3. 建立活動作業包
4. 建立任務清單
5. 建立核銷檢查表
6. 建立照片需求清單
7. 建立簽到表
8. 建立通知排程
9. 更新Dashboard
10. 寫入操作紀錄

## 流程依賴

例如：

未建立活動ID
→ 不可建立任務。

未建立Drive資料夾
→ 不可建立文件歸檔。

--------------------------------------------------
【三、報名同步工作流程】
--------------------------------------------------

## 同步報名資料後

Workflow Engine 自動執行：

1. 建立報名資料
2. 建立或更新學員CRM
3. 更新活動報名數
4. 更新來源渠道統計
5. 更新學員興趣標籤
6. 建立通知待發送紀錄
7. 更新Dashboard

--------------------------------------------------
【四、事件觸發引擎】
--------------------------------------------------

## Event Engine 核心

Event Engine 負責：

- 監聽事件
- 觸發後續動作
- 建立事件佇列
- 執行自動更新
- 執行通知
- 執行同步

## 事件中心資料表

事件紀錄

欄位：

- 事件ID
- 組織ID
- 事件類型
- 事件來源
- 關聯活動ID
- 關聯資料ID
- 事件狀態
- 執行結果
- 錯誤訊息
- 重試次數
- 建立時間
- 更新時間

--------------------------------------------------
【五、活動異動事件】
--------------------------------------------------

## 活動改日期

Event Engine 自動執行：

1. 更新活動資料
2. 更新Google Calendar
3. 更新通知排程
4. 更新簽到表
5. 更新現場任務
6. 更新便當數量
7. 更新場地資訊
8. 更新Dashboard
9. 寫入異動紀錄

## 活動取消

Event Engine 自動執行：

1. 更新活動狀態
2. 停止通知排程
3. 停止招生
4. 發送取消通知
5. 更新Dashboard
6. 建立取消紀錄

- 活動ID
- 通知類型

- 發送狀態

- 錯誤訊息

--------------------------------------------------
【七、事件佇列系統】
--------------------------------------------------

## Queue Engine

避免系統同時執行過多工作。

例如：

- 大量通知
- 大量同步
- 大量照片處理
- Dashboard重算

全部改成事件佇列。

## 佇列資料表

事件佇列

欄位：

- 佇列ID
- 事件ID
- 任務類型
- 任務狀態
- 排程時間
- 執行時間
- 完成時間
- 錯誤次數

--------------------------------------------------
【八、錯誤處理與重試機制】
--------------------------------------------------

## Retry Engine

若流程失敗：

- 自動重試
- 紀錄錯誤
- 發送管理通知
- 標記異常流程

## 重試規則

第一次失敗：5分鐘後重試
第二次失敗：15分鐘後重試
第三次失敗：通知管理員

--------------------------------------------------

【十、完成標準】
--------------------------------------------------

GovOps OS 需達成：

- 建立活動可自動建立所有後續流程
- 活動異動可自動同步所有相關資料
- 通知可自動排程

- 系統錯誤可自動重試

- 所有流程都可追蹤
